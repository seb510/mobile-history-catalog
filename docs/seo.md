# SEO та підготовка до індексації

Сайт залишається локальним. Поточний режим: `SEO_INDEXABLE=false` за замовчуванням, robots забороняє сканування, HTML містить `noindex`. Це не контроль доступу: приватні матеріали потребували б автентифікації.

## Що реалізовано

- Окремі заголовки й описи головної, каталогу, брендів, порівняння та About трьома мовами; назва, рік і призначення сторінки в заголовках моделей.
- Canonical без query-параметрів. Комбінації порівняння та фільтри не створюють окремі пошукові сторінки.
- Для контенту без перекладу canonical веде на фактичну мову джерела. `hreflang` містить лише окремі переклади та `x-default`; fallback-сторінки залишаються доступними для користувача.
- Статичний `/sitemap.xml`: основні сторінки й справжні мовні версії моделей/брендів, без 404, fallback-дублів і URL параметрів. Дата збірки не видається за дату оновлення контенту.
- `/robots.txt` генерується за режимом індексації; усі 404 містять `noindex` незалежно від режиму.
- JSON-LD `WebSite`, `WebPage` / `CollectionPage` / `AboutPage`, видимі хлібні крихти `BreadcrumbList`. Телефон позначено як тему сторінки (`Thing`). Історичні ціни не подаються як актуальні пропозиції магазину; рейтинги, відгуки та автори не вигадуються.
- Open Graph / Twitter із назвою сайту й зображеннями; дозвіл великих прев’ю для публічного режиму.
- На сторінці моделі — до трьох телефонів того самого бренду з найближчих років і посилання на порівняння. Основний текст fallback має атрибут фактичної мови.
- `npm run audit:seo` перевіряє зібраний `dist`: метадані, H1, JSON-LD, canonical, взаємність hreflang, sitemap, унікальність заголовків у sitemap і режими robots.

## Коли буде готовий публічний домен

1. Встановити `SITE_URL=https://ваш-домен` і `SEO_INDEXABLE=true` лише для production build. Відсутній або тестовий домен не підміняти доменом localhost. У preview залишати `SEO_INDEXABLE=false`. Налаштування читаються зі змінних середовища або локального `.env`; приклад — `.env.example`.
2. Виконати `npm run build`, потім `npm run audit:seo` з тим самим `SEO_INDEXABLE=true` у середовищі. Переконатися, що canonical, OG і sitemap містять один правильний HTTPS-домен.
3. При налаштуванні хостингу перевірити справжній HTTP 404 для відсутніх сторінок, єдиний HTTPS/host і редиректи старих URL. Не налаштовувати SPA fallback із відповіддю 200 на все.
4. Після публікації підтвердити власність домену в Google Search Console, надіслати `/sitemap.xml`, перевірити головну й кілька моделей через URL Inspection, а breadcrumbs — через Rich Results Test.
5. Перевірити мобільну швидкодію на публічному сайті. Віддалені фото Commons і мережеві ліміти потребують окремого контролю; успішна локальна збірка не доводить добрі Core Web Vitals.

Далі SEO розвивається редакційно: повні переклади, перевірені джерела для кожної моделі, змістовні історії епох і пояснення технологічних змін. Автоматичні ключові слова, десятки порожніх сторінок фільтрів і вигадані рейтинги цього не замінюють. Позиції та строки індексації не гарантуються.
