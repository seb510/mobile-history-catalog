# Що зберігати в Git

## Комітити

- `src/` — компоненти, стилі, маршрути та всі локалізовані дані.
- `public/` — статичні ресурси, включно зі згенерованими favicon PNG та `og-image.png`: сайт використовує їх без окремого кроку генерації під час збірки.
- `scripts/` — генератори, перевірки даних і Windows/Vite workaround, який імпортує конфігурація Astro.
- `package.json` і `package-lock.json` — залежності та відтворювані версії.
- `astro.config.mjs`, `tsconfig.json`, `.gitignore` та майбутню конфігурацію деплою без секретів.
- `AGENTS.md`, `CLAUDE.md`, `README.md`, `docs/` — правила роботи, джерела й результати перевірок.
- `.vscode/extensions.json`, `launch.json`, за потреби `tasks.json` — спільні рекомендації та запуск без особистих шляхів/секретів.
- Санітизовані шаблони `.env.example`, `.env.<режим>.example`, `.dev.vars.example` — лише назви змінних і безпечні приклади.

## Не комітити

Залежності `node_modules/`, збірку `dist/`, стан Astro/Vite/Cloudflare (`.astro/`, `.vite/`, `.wrangler/`), кеші, логи, локальні `.env*` / `.dev.vars*`, результати тестів, тимчасові каталоги та персональні налаштування IDE.

`docs/asset-audit.json` лишається версіонованим як знімок перевірки, а не кеш: його HTTP-статуси відображають момент запуску, а 429 не означає зламане фото. `docs/nokia-siemens-inventory.md` також варто комітити разом із генератором `scripts/audit-phone-data.mjs`, щоб зміни повноти даних було видно в diff.

`.gitignore` не прибирає вже відстежувані файли. Під час цього аудиту відстежуваних файлів, які підпадають під правила ігнорування, не виявлено; змінювати індекс Git не знадобилося.
