# Зворотний зв’язок → Telegram

Стан: 9 листопада 2026. Інтерфейс і серверний обробник підготовлені. Реального бота/чату в репозиторії немає; доставки в Telegram ще не перевірено. Ніякого деплою агент не виконував.

## Поведінка

Фіксована кнопка «Допомогти архіву» на всіх сторінках, uk/ru/en. Вона прихована за банером приватності та відкритим меню/діалогом, щоб елементи не перекривалися. Форма — native dialog, на мобільному знизу, на desktop по центру; працює у журналі й modern, у двох темах.

Типи: новий телефон, виправлення даних, баг, ідея. Для нового телефона є input+datalist бренду та залежної моделі. Це нативні пошукові поля зі свободою введення, не вимога обирати лише підказку; браузер без datalist лишає звичайне поле. `SUGGESTED_MODELS` — курована добірка, НЕ всі випущені телефони. Жоден зовнішній API не викликається при пошуку. Додавання повного manufacturer-wide довідника потребує окремих джерел і перевірки.

Поточні моделі та specVariant виключаються з підказок через нормалізовану пару brand+model (`NFKC`, без пунктуації/пробілів, без регістру). Ручне введення точної нормалізованої назви вже наявного телефона блокується в браузері. Це UX-перевірка, не серверний захист від довільно сформованих запитів; альтернативні назви не завжди розпізнаються.

Обов’язковий опис 10–1800 символів, необов’язкові джерело HTTP(S) та email. До звернення додається лише pathname сторінки без query/hash: порівнювані моделі з URL й персональні дані браузера автоматично не пересилаються. Власні періоди/телефони та cookies не надсилаються. Чернетка живе лише у відкритій сторінці, не в localStorage. Успіх показується тільки за підтвердженням Telegram `ok:true`; помилка не очищує поля. Технічний timeout не виключає, що Telegram уже встиг прийняти звернення: автоматичних повторів немає.

## Архітектура

Усі сторінки залишаються Astro SSG. Новий `worker/feedback.mjs` виконується лише для `/api/feedback` завдяки `assets.run_worker_first`. Решта — статичні `dist` assets, 404 лишається справжнім 404. Cloudflare-адаптер Astro не потрібний. Це свідоме розширення попередньої архітектури «взагалі без Worker-коду».

POST JSON на тому самому origin. Перевірки: метод, Origin, Content-Type, обмежений потік body 10KB, поля/URL/довжини; honeypot, binding FEEDBACK_RATE_LIMIT (3 запити/60с на ключ/локацію). Ліміти Cloudflare приблизні, не глобально точні; активний ботнет вони не усувають. Не додавався сторонній CAPTCHA/трекер. Хеш IP використовується як ключ ліміту, не включається у повідомлення. Немає власної бази повідомлень, parse_mode або зовнішніх link previews. Доставка лише на фіксований серверний chat_id; токен ніколи не віддається браузеру. Системні помилки/токени/тіла повідомлень не логуються застосунком.

## Підключення власником

1. Створити бота через офіційний [BotFather](https://t.me/BotFather) і отримати токен. Не вставляти токен у чат агента, репозиторій, PUBLIC_* чи браузерний код.
2. Відкрити свого бота й надіслати `/start`. Отримати власний chat_id через метод `getUpdates` Bot API у приватному локальному середовищі. Не публікувати відповідь: вона може містити приватні повідомлення. Для групи спершу додати туди бота й перевірити права надсилання.
3. Для локального Worker скопіювати `.dev.vars.example` → `.dev.vars` і заповнити TELEGRAM_BOT_TOKEN та TELEGRAM_CHAT_ID. `.dev.vars` ігнорується Git.
4. `npm ci`, `npm run build`, потім `npx wrangler dev --port 8787`. Відкрити адресу Wrangler (сайт і API разом). Звичайний `astro dev` показує форму, але не запускає Worker: надсилання поверне зрозумілий стан «ще не підключене».
5. Для production власник додає **Secrets** TELEGRAM_BOT_TOKEN та TELEGRAM_CHAT_ID у Workers settings або через інтерактивні `npx wrangler secret put TELEGRAM_BOT_TOKEN` та `npx wrangler secret put TELEGRAM_CHAT_ID`. Не додавати значення в wrangler.jsonc. Binding rate limit уже описаний у config; namespace_id має бути окремим від інших лімітів облікового запису.
6. Власник перевіряє повідомлення в правильному приватному чаті; після цього сам виконує push/deploy за звичним `npx wrangler deploy --autoconfig=false`. Агент не виконує ці дії без належної вказівки. `--autoconfig=false` лишається необхідним.

Без secrets/лімітера API повертає 503, а не удаваний успіх. Перевірте конфігурацію Wrangler та rate-limit binding у своєму середовищі перед публікацією. Ротація скомпрометованого токена — через BotFather.

## Файли та перевірки

- `src/components/Feedback.astro`, `src/scripts/feedback.ts`, `src/styles/feedback.css` — інтерфейс.
- `src/lib/feedback.ts` — тримовні тексти й добірка моделей.
- `src/layouts/Layout.astro` — глобальне підключення.
- `worker/feedback.mjs`, `wrangler.jsonc`, `.dev.vars.example` — доставка/налаштування.
- `src/lib/privacy-copy.ts` — повідомлення про передачу даних, три мови. Видалення звернень у Telegram ручне: строки/процес має підтримувати власник; автоматичного видалення немає.
- `npm run test:feedback` — ізольовані Node tests з підміною HTTP-транспорту, без реального надсилання. Перевіряють захист/валідацію, успіх/помилки доставки, ліміт і fallback static assets.
- `npm run build`, `npm run audit:seo`, `npm run audit:locales` — загальні перевірки.

Реальну доставку без secrets не тестували; Node mocks не підтверджують права бота чи production rate-limit. Потрібна контрольна відправка власником після налаштування.

Джерела реалізації: [Telegram sendMessage](https://core.telegram.org/bots/api#sendmessage), [Cloudflare Worker + static assets](https://developers.cloudflare.com/workers/static-assets/routing/worker-script/), [Cloudflare rate limits](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/).

## Production-перевірка — 2026-11-09

На прохання власника перевірено публічний origin. Глобальна кнопка й діалог працюють; GET /api/feedback повертає JSON 405, отже Worker-обробник опублікований. Тестове звернення Codex, пропозиція Siemens M55 і окреме побажання (прикріплення скриншота) через UI повернули «Надсилання ще не підключене». Успіху Telegram не підтверджено; тексти збережені у формі при помилці. Це не додавання M55 до каталогу. Перевірити production secrets TELEGRAM_BOT_TOKEN / TELEGRAM_CHAT_ID і binding FEEDBACK_RATE_LIMIT; значення секретів агенту невідомі й не читались. Повторити реальне надсилання після налаштування власником.
