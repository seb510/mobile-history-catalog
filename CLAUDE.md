# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

**Мобільна Історія** — курований архів ретро-телефонів із характером: виразні корпуси, клавіатури, механізми, матеріали, музичні й камерні сценарії кнопкової епохи. Таймлайн починається з 1998–1999; сучасні сенсорні моделі збережені як продовження історії, але не її центральний сюжет. Головний критерій добору — дизайн і досвід користування, а не лише технічна першість чи продажі. Порівняння (/compare/, React-острівець) допомагає досліджувати різні характери телефонів. Це не повний каталог і не конкурент GSMArena.
Натхнення редакційною подачею — український журнал MobiLux (2004–2016): виразна «обкладинка» з
моделлю, помітна типографіка, короткий редакційний текст і компактні технічні характеристики.
Адаптуй цю енергію й журнальну ієрархію до сучасної взаємодії. Сестринський проєкт
до [Watchly](../watchly) (той самий автор, та сама загальна філософія: легальні джерела даних,
Cloudflare Workers деплой), але інша архітектура — тут усе статично генерується (Astro SSG), бо
дані курируються вручну й незмінні між білдами, на відміну від живих API в Watchly.

## Commands

```
npm run dev        # dev server at localhost:4321 (see also "Development" below for background mode)
npm run build       # type-checks + builds static site to dist/
npm run preview     # serve the built dist/ locally
npm run astro check # type-check content frontmatter against the Zod schema without a full build
```

A focused feedback API test suite is available via `npm run test:feedback`; no general UI test suite or linter is configured. There is no per-phone "test" — correctness is enforced by
the Zod schema in `src/content.config.ts` at build time; `npm run build` (or `astro check`)
failing on a phone file is the equivalent of a failing test.

## Архітектура

Сайт триязичний (uk/ru/en, uk — дефолт без префікса в URL, `/ru/*` і `/en/*` — префіксовані),
через Astro-вбудований i18n-роутинг (`astro.config.mjs`, `i18n.routing.prefixDefaultLocale: false`).
Оскільки Astro не перекладає content collections автоматично, кожен роут продубльовано вручну
по локалі (`src/pages/phones/[slug].astro`, `src/pages/ru/phones/[slug].astro`,
`src/pages/en/phones/[slug].astro` — і так само для `/`, `/catalog/`, `/about/`); кожен такий файл
тонкий — просто фіксує `locale` і делегує рендер спільному компоненту. Додаючи нову сторінку,
додавай усі 3 локальні варіанти одразу.

- `src/content.config.ts` — колекція `phones`, glob-завантажувач `src/data/phones/*/*.md`
  (локаль — перша директорія: `uk/nokia-3310.md`). Zod-схема в цьому файлі — єдине джерело правди
  про обов'язкові (`brand`, `model`, `year`) проти опціональних специфікацій. Нове поле специфікації
  означає: оновити схему тут **і** канонічний список полів `FIELDS` у `src/lib/specs.ts`.
- `src/lib/specs.ts` — єдиний канонічний (упорядкований, згрупований) список полів специфікацій;
  `buildSpecGroups(data, strings)` будує рядки одного телефона (
  пропускає відсутні поля), `buildCompareGroups(dataA, dataB, strings)` — для `/compare/` (рядок
  лишається, якщо значення є хоч в одного з двох, інакше — "—"). Обидва споживача завжди лишаються
  синхронізованими, бо беруть рядки з одного джерела. У таблицях групи полів відділені виразними
  межами, назви характеристик мають окрему колонку, а таблиця порівняння показує моделі в заголовку.
- `src/lib/locales.ts` + `src/lib/phones.ts` — локаль-типи й fallback-ланцюжок (uk → ru → en для
  ru-сторінок, en → uk → ru для en-сторінок; uk завжди має файл, тому для uk fallback не потрібен).
  `getPhone(locale, slug)` і `getPhonesForLocale(locale)` — єдина точка доступу до контенту з
  урахуванням fallback; не читай колекцію напряму в сторінках.
- `src/lib/ui-strings.ts` — словник текстів інтерфейсу (нав, футер, фільтри, підписи специфікацій,
  крихти, мобільне меню й перемикач теми, сторінка "Про проєкт") окремо від контенту телефонів,
  який живе в markdown. `src/lib/seo.ts` — будує canonical/hreflang/og:locale для `<head>`.
- Inline-скрипт у `src/layouts/Layout.astro` призначає зовнішнім HTTP(S)-посиланням `target="_blank"`
  і додає `rel="noopener noreferrer"`; внутрішні посилання лишаються в цій вкладці. Для статичних
  зовнішніх посилань у компонентах також виставляй ці атрибути явно в розмітці.
- `src/components/Breadcrumbs.astro` — спільна локалізована навігація для каталогу, брендів,
  порівняння, сторінки про проєкт, сторінок телефонів і брендів та 404; посилання формуються через
  `localePath()`, останній елемент позначається `aria-current="page"`.
- `src/layouts/Layout.astro` — єдиний layout: повний SEO `<head>` (title/description/canonical/
  hreflang на всі 3 локалі/OG/Twitter) + `Header` + `Footer`. Приймає `path` (без префікса локалі,
  однаковий для всіх 3 мов) — з нього будуються canonical і перемикач мов. Header локалізує кнопки
  меню й теми; мобільне меню недоступне Tab-навігації у згорнутому стані, закривається Escape.
  Footer повторює бренд і основні маршрути та показує відомості про ліцензування контенту.
- `src/pages/index.astro` (+ ru/en) — hero-головна (`src/components/Hero.astro`): заголовок,
  статистика каталогу, недавні поповнення, тематичні добірки й принципи проєкту. unitsSoldMillions зберігається лише для публічно підтверджених цифр, це не основа поточної композиції головної.
- `src/pages/catalog/index.astro` (+ ru/en) — повний каталог з фільтрами (`src/components/
  Catalog.astro`): бренд/рік/пошук, клієнтський vanilla JS (без React) фільтрує картки за
  `data-*`-атрибутами й ховає порожні річні групи; річні групи зібрані у вертикальну часову
  вісь із точками-роками.
- `src/pages/phones/[slug].astro` (+ ru/en) — `getStaticPaths` зі `getAllSlugs()` (слаги з uk-файлів
  — вони завжди є), рендер через `src/components/PhoneDetail.astro`.
- `src/pages/compare/index.astro` (+ ru/en) — порівняння двох телефонів пліч-о-пліч. Тонка сторінка
  делегує в `src/components/Compare.astro` (Astro, тягне `getPhonesForLocale` і передає слім-список
  `{slug, data}` як серіалізовані props), що рендерить `src/components/CompareIsland.tsx`
  (`client:load`) — єдиний React-компонент у проєкті: пошук-вибір телефону в кожен з двох слотів
  (фільтрація по `brand model year`, виключає вже обраний у другому слоті телефон), стан вибору
  синхронізується в URL (`?a=slug&b=slug`, `history.replaceState`) для share-посилань і
  deep-linking, таблиця будується через `buildCompareGroups` з `src/lib/specs.ts`. У порожньому
  стані без вибраних моделей показує кілька курованих пар; їхні описи локалізовані в
  `src/lib/ui-strings.ts`, а посилання відразу відкривають порівняння через query-параметри.
- `src/pages/brands/index.astro` (+ ru/en) — грід усіх брендів (`src/components/BrandsIndex.astro`).
  `src/pages/brands/[slug].astro` (+ ru/en) — сторінка бренду: коротка історія + вордмарк-лого +
  всі телефони бренду, через `src/components/BrandDetail.astro`. Окрема content-колекція `brands`
  (`src/content.config.ts`, `src/data/brands/<uk|ru|en>/<slug>.md`, той самий паттерн і fallback,
  що й у `phones` — див. `src/lib/brands.ts`). Поле `name` у фронтматері бренду має **точно**
  збігатися зі значенням `brand` на телефонах — по ньому `BrandDetail.astro` фільтрує телефони
  бренду. `slugifyBrandName()` (з `lib/brands.ts`) робить slug прямо з `brand`-рядка телефону
  (напр. "Sony Ericsson" → "sony-ericsson") — цим лінкується `PhoneDetail.astro` на сторінку
  бренду без зайвого запиту колекції; slug файлу бренду мусить збігатися з цим виводом.
- `src/components/BrandMark.astro` — лого бренду на **фіксовано білій** плашці (не залежить від
  теми сайту): реальні вордмарки з Wikimedia Commons часто мають свій колір заливки (інколи
  майже чорний або білий), тому на змінному фоні легко стають нечитабельними — консистентна біла
  підкладка це знімає. Якщо вільного лого не знайдено — фолбек: `name` текстом, **обов'язково**
  `text-black` (не `text-neutral-900`!), бо `neutral-*` у темі інвертується, а ця плашка — ні.
  Лого — тільки з Wikimedia Commons, тільки з чіткою вільною ліцензією (`PD-textlogo`/public
  domain — такі теги зазвичай мають прості текстові вордмарки; НЕ "non-free/fair use only",
  той статус не дозволяє використання поза Wikipedia). Товарний знак лишається товарним знаком
  навіть у суспільному надбанні з погляду авторського права — це нормально для номінативного,
  неторгового використання (ідентифікація бренду в каталозі), якщо для бренду немає перевіреного вільного файлу — лиши `logo` незаповненим.
  Для Apple на запит користувача використовується знак яблука з Commons (`Apple_Logo.svg`,
  PD-textlogo); для Huawei — `Huawei_wordmark.svg` (PD-textlogo).
- Лого (`src/components/LogoMark.astro`, `public/favicon.svg`) — власний абстрактний кнопковий телефон: екран, навігаційна риска й сітка 3×3 клавіш на помаранчевій плашці. Це оригінальний знак, не копія моделі чи бренду. Назва лишається «Мобільна Історія», позиціонування — «Телефони з характером» (brandLine у ui-strings.ts; uk/ru/en).
  `scripts/generate-images.mjs` використовує сам favicon.svg у OG-шаблоні; після зміни знака запускай gen:images і додавай PNG assets до коміту. Геометрію glyph синхронізуй також у PlaceholderArt.astro й PlaceholderIcon у CompareIsland.tsx. Зображення телефонів мають data-image-fallback і приховану заглушку; src/scripts/image-fallback.ts перемикає їх при помилці. BrandMark має власний текстовий fallback.
- Світла/темна тема — перемикач (`src/components/ThemeToggle.astro`) ставить `data-theme="light"|
  "dark"` на `<html>` і зберігає вибір у `localStorage('theme')`; блокувальний inline-скрипт на
  початку `<head>` в `Layout.astro` застосовує збережений вибір до першого рендеру (без цього —
  спалах не тієї теми). Сам перемикач кольорів — **не** класи `dark:` на кожному елементі, а
  інверсія CSS-змінних Tailwind-палітри (`--color-neutral-*`, `--color-orange-*`) у
  `src/styles/global.css` під `[data-theme="light"]` / `@media (prefers-color-scheme: light)`:
  існуючі класи (`bg-neutral-950`, `text-neutral-400` тощо) автоматично відображають правильну
  тему без жодних змін у розмітці компонентів. Додаючи новий колір за межами `neutral`/`orange` —
  додай його інверсію в той самий CSS-блок, а не `dark:`-варіант на елементі.
- Візуальна система — теплий паперовий фон у світлій темі, чорнильні нейтралі в темній і мідний
  редакційний акцент (токени orange-*); використовуй журнальну сітку, сильні заголовки, тонкі розділювачі, стримані
  тіні й невеликі заокруглення. Під час дизайн-проходу працюй із наявними записами; нові моделі
  додавай після окремого запиту користувача.
- Основна ширина контенту — `max-w-6xl` для спільного вирівнювання layout, header і footer. Hero
  дає короткий маршрут до каталогу й порівняння; каталог та сторінка брендів мають редакційний
  вступ із підзаголовком. Картки телефонів зберігають спільне співвідношення фото й мінімальну
  висоту текстового блоку, картки брендів завжди показують назву та кількість моделей. Форми
  лічильника локалізуй через `strings.brands.phoneCount` (one/few/many для uk/ru, one/many для en)
  і вибирай за правилами множини відповідної локалі.
- Розділ About має пояснювати не лише історію й критерії добору, а й практично як шукати у
  таймлайні та як поділитися порівнянням; підтримуй ці пояснення синхронними трьома мовами.
- Посилання в тексті Markdown стилізуй через `src/styles/global.css` як помаранчеві посилання з
  підкресленням, щоб вони залишалися читабельними в обох темах навіть усередині `prose-invert`;
  клікабельні кредити фото в `PhoneDetail.astro` використовують той самий помаранчевий стиль.
- Колір `text-neutral-500` підібраний із контрастом для дрібних підписів на фонах карток у темній
  і світлій темах; якщо змінюєш палітру нейтралів у `global.css`, перевір контраст metadata, labels,
  placeholder-текстів і другорядних посилань на обох темах.
- Ховер-ефекти — лише на пристроях з мишкою: кастомний Tailwind-варіант `hover-desktop:`
  (визначений у `src/styles/global.css` через `@custom-variant`, `@media (hover: hover) and
  (pointer: fine)`) замість стандартного `hover:` для декоративних станів (не для `focus:`).
  Анімації та переходи мають поважати `prefers-reduced-motion`.
- Спільна система руху визначена в `src/styles/global.css`: `--motion-ui`, `--motion-image`,
  `--motion-enter` і `--motion-easing`; використовуй утиліти `motion-ui`/`motion-image` замість
  випадкових `duration-*`. Рух має бути коротким і стриманим, а підйом карток — ледь помітним.
- Таблиці характеристик і порівняння компактні на вузьких екранах, але на широких (`lg:`) мають

## Дані

Один телефон = до 3 Markdown-файлів, по одному на локаль: `src/data/phones/<uk|ru|en>/<slug>.md`.
`uk/<slug>.md` обов'язковий і курирується першим (найповніший); `ru`/`en` — опційні переклади
(milestone-тег + тіло). Специфікації (frontmatter) дублюються в кожному файлі, а не виносяться в
спільний — каталог малий і курований вручну, тож дублювання дешевше за крос-референсну систему.
Slug = ім'я файлу без розширення, однакове в усіх трьох локалях (не перекладається).

Актуальне охоплення каталогу: після 2019 року додано iPhone 12 (2020), Galaxy Z Fold3 (2021),
Huawei Mate XT (2024) і Galaxy S26 Ultra (2026). Нові записи курируй як етапи індустрії, а не
як повне покриття кожного року; для нових брендів додавай сторінку бренду, щоб лінк із телефону
не вів на відсутній маршрут.

Зображення: головне фото — `image` + `imageCredit` + `imageSourceUrl`; додаткові фото — в
опційному `gallery` (кожен об'єкт обов'язково має `image`, `alt`, `imageCredit`, `imageSourceUrl`).
Галерея на сторінці
телефону показує мініатюри з перемиканням мишкою й клавіатурними стрілками; attribution змінюється
разом із фото. Кнопка поверх головного фото відкриває повноекранний перегляд: стрілки та кнопки
перемикають кадри, Escape або кнопка закриття повертають до сторінки. Типове джерело — вільно ліцензовані фото з
Wikimedia Commons (не press-кіти виробників — ті майже завжди copyrighted): відкрити сторінку
File: на Commons, перевірити ліцензію (CC BY/BY-SA — ОК; "all rights reserved" — ні), узяти пряме
посилання на `upload.wikimedia.org` (не сторінку File:) у форматі
`.../commons/thumb/<a>/<ab>/<Назва.jpg>/960px-<Назва.jpg>` — Wikimedia віддає тільки
"стандартні" ширини thumbnail'ів (960, 1280, 1920 px; повний список — commons "Common thumbnail
sizes"), довільна ширина на кшталт `800px-` поверне 429/400. `imageCredit` — короткий підпис
(автор + ліцензія), `imageSourceUrl` — посилання на саму сторінку File: (не на картинку) для
перевірки; `PhoneDetail.astro` рендерить `imageCredit` як клікабельне посилання, коли
`imageSourceUrl` заданий. Без `image` рендериться `PlaceholderArt`; якщо задане зображення не
завантажиться, обробник у `src/scripts/image-fallback.ts` показує ту саму заглушку в картці,
деталі телефону та слоті порівняння.

Бренди — той самий паттерн у `src/data/brands/<uk|ru|en>/<slug>.md`: `name` (має збігатись із
`brand` на телефонах), опційні `founded`/`country`, опційне лого (`logo`/`logoCredit`/
`logoSourceUrl`, правила сорсингу — див. `BrandMark.astro` вище), тіло — коротка історія бренду.

## Деплой

Налаштовано 2026-10-31: `wrangler.jsonc` у корені — Cloudflare Workers зі статичними asset'ами,
як у Watchly (`npm run build` видає повністю статичний `dist/`; Worker-код не потрібен, на відміну
від Watchly, де є виняток для `/show/*`, — тут кожна сторінка вже статична HTML, включно з 404).
`assets.not_found_handling: "404-page"` явно віддає `dist/404.html` зі справжнім HTTP 404 для будь-
якого невідомого шляху (без SPA-фолбеку на 200). `name` ("mobile-history-catalog") мусить збігатися
з назвою проєкту (Worker) у дешборді Cloudflare. `.node-version` (24) фіксує версію Node для Workers
Builds, як у Watchly. `npx wrangler deploy --dry-run` локально підтверджує валідність конфігу (714
файлів із `dist/`, без bindings) без фактичного деплою.

**Відомий гачок (2026-10-31):** перший реальний деплой через Workers Builds упав. `npx wrangler deploy`
(4.156.0) має увімкнене за замовчуванням "autoconfig" — виявляє фреймворк (тут: Astro) без Cloudflare-
адаптера й сам запускає `astro add cloudflare`, що додає `@astrojs/cloudflare` і пересобирає сайт через
workerd-рантайм для "generating static routes"; саме там падає (`Uncaught TypeError... Received
'undefined'` у `chunks/react_Drpegsay.mjs` — несумісність адаптера з React-чанком у CI). Це суперечить
навмисному рішенню тримати сайт чисто статичним (без Worker-коду/адаптера). Виправлення: **Deploy
command** у налаштуваннях Workers-проєкту в дешборді Cloudflare має бути `npx wrangler deploy
--autoconfig=false`, а не просто `npx wrangler deploy`. Локально `--autoconfig=false` підтверджено
(знову читає `dist/` напряму, без спроби додати адаптер).

Публічний Workers origin уже налаштований: https://mobile-history-catalog.nikolaysebistiyan.workers.dev/. Попередня перевірка production задокументована 2026-11-05; цей документаційний прохід не перевіряє актуальний deployment чи його індексацію. Build command — npm run build; deploy command — npx wrangler deploy --autoconfig=false. SITE_URL та SEO_INDEXABLE задає власник для відповідного середовища. Агент не пушить і не запускає деплой.

## SEO до публікації

Правила й запуск: docs/seo.md. SITE_URL задає origin, SEO_INDEXABLE=true дозволяє індексацію лише для публічної збірки; за замовчуванням noindex і robots Disallow. Конфіг читає env через Vite loadEnv; приватні значення не передаються клієнту. src/lib/search-index.ts визначає фактичну мову контенту, canonical/hreflang і 117 адрес sitemap (після поточних 69 моделей). Fallback-контент не вважається перекладом; sitemap виключає fallback і 404. src/lib/search-copy.ts — локалізовані SEO-тексти; StructuredData.astro безпечно серіалізує JSON-LD. Не вигадувати рейтинги, Offer, авторів або дати. npm run audit:seo перевіряє dist після build. Перевірено обидва режими: 252 HTML / 117 canonical URL. Перед публікацією потрібні домен, production-перемикач, HTTP-редиректи/404 та Search Console; деплой і push агент не виконує.

## Компактніші фільтри каталогу на мобільному — 2026-10-30

Під час правки виявлено реальний CSS-баг: перші чернетки цих правил додавались у ранній `@media (max-width: 639px)` блок (рядок ~316), який у файлі стоїть ПЕРЕД базовими unprefixed-правилами (`.catalog-tools`, `.catalog-filter-meta`, `.filter-select-trigger` тощо) та перед пізнішим `@media (max-width: 1023px)` блоком — за рівної специфічності пізніше правило в каскаді перемагає незалежно від медіа-умови, тож мої зміни просто ігнорувались браузером. Виправлено: новий `@media (max-width: 639px)` блок додано в кінець файлу, одразу після `@media (max-width: 1023px)`, — так само, як цей файл уже структурує подібні перевизначення в інших місцях. Перевірено через `getComputedStyle`/`getBoundingClientRect` у браузері до і після виправлення, щоб переконатись, що правила справді застосовуються, а не просто виглядають коректно в редакторі.

`GlobalSearch.astro` доступний у спільному хедері на всіх сторінках; результати повного пошуку показує `/search/` (uk, ru, en). `search-index.json.ts` генерує статичний локалізований індекс із `getPhonesForLocale()`. ## Liquid Glass — 2026-11-08

Сучасна редакція має веб-інтерпретацію Liquid Glass: плаваючий хедер, напівпрозорі навігаційні панелі, м’які відблиски та капсульні кнопки. Історії й таблиці зберігають щільний фон. Новий останній шар CSS — `src/styles/liquid-glass.css` після `phone-detail.css`, лише під `data-design="modern"`. Без шейдерів, відстеження курсора чи постійних анімацій. Є fallback без backdrop-filter, режими reduced-transparency / contrast / forced-colors; рух поважає reduced-motion. Каталог враховує верхній відступ плаваючого хедера. Журнальна редакція збережена. Це веб-інтерпретація матеріалу Apple, а не нативний API iOS.

### Посилений скляний матеріал — 2026-11-08
Modern: льодяно-блакитна світла палітра й графітова темна, напівпрозорі картки та панелі всіх маршрутів (каталог, бренди, порівняння, мої телефони, About, оновлення, приватність/cookies). Більше крайових відблисків, м’які кольорові засвічення; мідні CTA збережено. Blur лише на великих панелях/навігації, не на кожній картці. Таблиці щільніші. Reduced transparency/contrast дають суцільний матеріал.

Скляні hover-стани: лише fine-pointer/hover — крайовий відблиск, глибша тінь, підйом клікабельних карток 2px; кнопки мають світлову грань і стриманий press. Немає анімації blur. Reduced-motion вимикає переходи й рух; клавіатурний focus лишається виразним.

### Знак бренду — 2026-11-08
Оновлено оригінальний знак: графітово-синя плашка зі світлою гранню, ретро-корпус, мідний екран, навігаційне кільце й капсульні клавіші. Спільний для обох редакцій і тем. Геометрія синхронна в LogoMark, favicon, PlaceholderArt і CompareIsland; PNG/OG перегенеровано через gen:images. Назву не змінено.

Футер modern — окрема скляна панель з відступом від країв, явний світлий колір footer-brand незалежно від інверсії neutral; знак 40px, нижні службові рядки компактніші.

На прямий запит посилено backdrop blur на скляних поверхнях modern: контент 20px / 12px mobile; навігація 32px / 24px mobile. У generation-feature фільтр лише на контейнері. Blur не анімується. Reduced transparency/contrast/forced colors вимикають фільтри. Попереднє обмеження blur лише великими панелями замінено цим рішенням; продуктивність на фізичних слабких пристроях потребує перевірки власником.

Мобільне меню: нумерацію пунктів прибрано в обох редакціях. Modern має легкі прозорі рядки, скляне виділення активного маршруту, вирівняні стрілки та компактні налаштування. Лічильник власних телефонів збережено.

### Бірюзовий акцент modern — 2026-11-08
Сучасна редакція: orange-* сумісні токени тепер бірюзові — #087F8C для тексту в light, #67D9DF у dark; суцільні CTA #087783 з білим текстом. Темний футер і RAZR-панель мають світлий бірюзовий незалежно від теми. Журнальна редакція й власний мідний екран знака збережені. Замінює попередню спільну мідну палітру двох редакцій.

На прохання власника тіні modern мінімізовано: контент лише з внутрішньою світлою гранню, плаваючі панелі з легкою тінню 4px/12px, hover 3px/9px. Об’єм забезпечують прозорість та blur.

Галерея глобально: іконка розгортання замість текстової кнопки; масштаб — лупа +/− з динамічними aria-label/title uk/ru/en. Плавна поява кадрів та fullscreen, згасання закриття (включно Escape); reduced-motion вимикає рух. Навігацію, captions/credits, свайп і масштаб збережено.

Порівняння: compare-table використовує overflow:clip замість hidden і без backdrop-filter на контейнері, щоб sticky-заголовок не створював порожню смугу 60px; фон залишається скляним, top враховує плаваючий хедер.

Sticky порівняння збережено: верхній відступ вимірюється від фактичної висоти/позиції хедера через ResizeObserver; при приховуванні хедера top=0. Перемикання редакції та resize перераховують відступ.

## Зворотний зв’язок — 2026-11-09

Глобальна кнопка Feedback у Layout, діалог uk/ru/en у двох редакціях і темах; типи phone/correction/bug/idea. Бренд/модель — input+datalist з ручним введенням, підказки з lib/feedback.ts. Довідник курований, не повний список виробника. Наявні моделі та specVariant виключаються з підказок, ручні дублікати перевіряються в браузері. API не має повного довідника виробників.

Усі сторінки лишаються SSG; новий worker/feedback.mjs обробляє лише POST /api/feedback (run_worker_first), решта — ASSETS. Це актуальна зміна попередньої архітектури без Worker-коду; Cloudflare-адаптер Astro не додавати. TELEGRAM_BOT_TOKEN і TELEGRAM_CHAT_ID тільки secrets, локально .dev.vars (ignored); не просити токен у чаті й не додавати його до PUBLIC_* або Git. Без secrets API повертає 503. Ліміт binding FEEDBACK_RATE_LIMIT, 3/60с на хешований IP-ключ/локацію; Origin/поля/обмеження body/honeypot. Доставку Telegram реально ще не перевірено — бота та secrets підключає власник. Детально: [docs/feedback-telegram.md](docs/feedback-telegram.md).

Форма передає pathname без query/hash, необов’язковий email і введені дані лише після Send; чернетки не зберігаються, localStorage не додається. Оновлено privacy uk/ru/en. npm run test:feedback — 20 ізольованих тестів API з mock-транспортом; це єдиний доданий набір тестів, загального лінтера/тестової системи UI немає. Push/deploy лишаються виключно власнику, commit за прямим запитом.

Production-тест 2026-11-09: форма й API опубліковані, але тестові звернення (включно Siemens M55) повертають «Надсилання ще не підключене». Реальна доставка Telegram не підтверджена. Власник має перевірити secrets токена/chat ID і FEEDBACK_RATE_LIMIT. Запис у docs/feedback-telegram.md. Нових моделей не додавали.

Діагностика feedback: підготовлено окремі 503-коди missing_bot_token / missing_chat_id / missing_rate_limit без значень секретів; 23 API tests. Production до цієї правки повертав лише unavailable, попри коректні назви на скріншотах. Точна причина ще не підтверджена; зміна потребує публікації власником.

Причина missing_bot_token уточнена повним скріншотом: Telegram secrets були в Build variables and secrets (поруч Deploy Hooks/Build cache), не в runtime Production Variables and Secrets. Build-секрети не передаються env Worker. Потрібно додати runtime-секрети; реальну доставку після цього ще перевірити. Попередня вказівка агента про правильний розділ була помилковою. Деталі docs/feedback-telegram.md.

Production-доставка Telegram підтверджена 2026-11-09: Wrangler secret list показав обидва runtime-секрети (без значень), POST Siemens M55 → 200/sent, власник підтвердив отримання скріншотом. Через форму успішно надіслано побажання про скриншоти та додаткове про короткий номер звернення. Це лише відгуки, не реалізація побажань і не додавання моделі. Старі повідомлення про unavailable вище — історія налагодження.

Публічний журнал оновлено: 2026-11-09 — форма зворотного зв’язку, залежні підказки та підтверджена доставка Telegram; запис 2026-11-08 доповнено Liquid Glass, бірюзовим акцентом modern, знаком/favicon, галереєю й sticky порівняння. Усі тексти uk/ru/en. M55 лишається пропозицією користувача, не поповненням каталогу.
